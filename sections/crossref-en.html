Execution Contextc back to ToC or Class ToC

IRI: https://w3id.org/rdf-connect#ExecutionContext

A qualified association that binds a runner (agent) to the processor instances (activities) it executes within a pipeline, and to the pipeline plan itself. As a subclass of prov:Association it qualifies the assignment of responsibility for those processors to their runner, and as a subclass of prov:ActivityInfluence it cites those processors directly with prov:activity.

Runner Serverc back to ToC or Class ToC

IRI: https://w3id.org/rdf-connect#RunnerServer

A server that hosts a runner and the processors it can execute, so that orchestrators connect to that runner as a TCP runner instead of starting it. Each runner implementation that offers such a server declares its own subclass.

consists ofop back to ToC or Object Property ToC

IRI: https://w3id.org/rdf-connect#consistsOf

Relates a pipeline plan to the execution contexts (qualified runner–processor associations), and is declared as the inverse of prov:hadPlan. Because prov:hadPlan goes from a prov:Association to the prov:Plan it follows, each execution context (Association) thereby records the pipeline plan (Plan) it follows, matching the PROV-O qualified-association pattern.
has domain

has range
Execution Context c
is inverse of
had Plan op

entrypointop back to ToC or Object Property ToC

IRI: https://w3id.org/rdf-connect#entrypoint

The folder location of the main script or module entry point of a JavaScript processor. The location is usually given as an IRI, resolved against the document that declares it, and can also be given as a string literal.

fileop back to ToC or Object Property ToC

IRI: https://w3id.org/rdf-connect#file

The file name containing the processor logic of a JavaScript processor. The location is usually given as an IRI, resolved against the document that declares it, and can also be given as a string literal.

implementation ofop back to ToC or Object Property ToC

IRI: https://w3id.org/rdf-connect#implementationOf

Abstract property that conveys the implementation language of a processor. As a subproperty of rdfs:subClassOf, any processor definition declared with rdfc:implementationOf rdfc:Processor is itself a subclass of rdfc:Processor, and therefore a class that a pipeline can instantiate. Its subjects and objects are classes rather than processor instances, which is why its domain and range are rdfs:Class.
has super-properties
sub Class Of op
has sub-properties
Java Implementation Of op, JavaScript Implementation Of op, Python Implementation Of op
has domain
Class c
has range
Class c

log leveldp back to ToC or Data Property ToC

IRI: https://w3id.org/rdf-connect#logLevel

Optional level at which an orchestrator logs the data written to a channel, such as info or debug. It is an aid while developing or inspecting a pipeline and has no effect on how messages are routed or delivered. Its domain is rdfc:Writer because an orchestrator logs each payload once, as the payload is submitted to the channel.
